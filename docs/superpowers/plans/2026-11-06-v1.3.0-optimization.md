## 2. Review findings (the reason for every task)

### P0 — correctness

**P0-1 Tool-call arguments are counted as output speed → AVG/calibration are badly inflated (most serious)**
- 📖 opencode computes `tokens.output = outputTokens - reasoningTokens` (binary `_S` function), so `output`
  **includes tool-call argument tokens**.
- The current timing window (`firstDelta..lastDelta`) only covers text/reasoning deltas, and on tool input start
  `clearSessionLive` clears the live samples (`tui.tsx:461/466/550`).
- Example: say 8 tokens (0.4s → clamped to 1s) then write a 2000-token file → AVG records "2008 tok / 1s"; the
  calibration ratio 2008/8 is clamped to 3.0 → all later live TPS is inflated up to 3×.
- 📖 Event availability:
  - V1 (SDK `@opencode-ai/sdk/v2` types, opencode ≥ ~1.18): `session.next.tool.input.delta`
    `{timestamp, sessionID, assistantMessageID, callID, delta}`. In the binary, `SessionRunner.publishLLMEvent`
    publishes it (along with `session.next.text.delta`, etc.).
  - V2 (`@opencode/client` 2.2.5): `session.tool.input.delta` `data: {sessionID, assistantMessageID, id, delta}`,
    timestamp in `evt.created`.
  - Legacy path (`message.part.delta`, used when `useV2Events=false`): the legacy SessionProcessor does
    **not** emit any delta for tool input (it only `updatePart`s with `state:{status:"pending",input:{},raw:""}`),
    so there is nothing to record → **the legacy path needs the "step excludes tool-calls" fallback** (see design
    §3.2).

**P0-2 Models that don't stream reasoning inflate the numbers too**
- e.g. o-series: `tokens.reasoning` is large but no reasoning delta is sent; the reasoning time is counted in TTFT
  while the tokens are counted in the AVG window.
- Fix: track per message whether a reasoning delta was seen; if not, exclude `tokens.reasoning` from AVG and from
  calibration.

**P0-3 A listener that outlives an unmount writes to a destroyed renderable → throws (✅ verified)**
- Unsubscribing relies solely on `onCleanup` (`:398-399`). If cleanup never runs (when `Owner` is null, `onCleanup`
  is a no-op), the stale `sync` keeps writing to `content`.
- ✅ Assigning `content` after `destroy()` throws: opentui 0.4.2 → `TextBuffer is destroyed`; 0.8.1 →
  `Native scene Yoga node is freed`.
- `bump()` (`:242`) has no try/catch: one listener throwing → every later listener is skipped; inside
  `setInterval` it becomes an uncaught exception.
- ✅ `renderable.isDestroyed` getter exists in both 0.4.2 and 0.8.1.

**P0-4 The spinner can spin forever after an interrupt or error**
- `thinkingBySession` is only reset on delta / completion / tool events. Missing reset points:
  - V1: `session.idle` `{sessionID}`, `session.error` `{sessionID?}` (📖 both are in the SDK types and emitted by the
    binary).
  - V2: `session.execution.succeeded|failed|interrupted` `data: {sessionID, ...}`.
  - Fallback: in the 1s tick, if thinking is true and the last delta is older than `STALE_MS`, turn it off
    automatically.

**P0-5 A completion event unconditionally clears the whole session's live state**
- `:345-347` doesn't check whether the completing message is the one currently streaming.
  `activeMessageBySession` is written but never read (`:213`).
- Fix: only clear samples/thinking when `active === info.id` (or no active message).

**P0-6 V2 sessionID is resolved only once at mount; the slot unregister function is discarded**
- `:572-575`: if the slot input doesn't carry a `sessionID`, switching sessions doesn't refresh the display.
- 📖 The V2 `render` input is a **reactive props object** (`PromptFooterInput = { sessionID?, mode, showDetails }`),
  so reading `input.sessionID` **inside sync** each time gets the latest value; only fall back to
  `ctx.ui.router.current()` when it's missing. Pass a getter instead of a value.
- `ctx.ui.slot()` returns `() => void` (📖 `@opencode/plugin` 2.2.5 `context.d.ts:477`); currently discarded
  (`:569`) → must be called during dispose.

### P1 — performance

**P1-7 Idle still forces a render every second**
- The 1s timers at `:474` / `:555` always run; each assigns `content` 4× and calls `requestRender()` every time.
- ✅ The `content` setter does no equality check: it builds a new StyledText and marks layout dirty every time
  (20k same-value assignments ≈ 226ms).
- Fix: cache the last rendered result and only assign/render when it changed; stop the tick entirely when there
  are no samples and nothing is thinking.

**P1-8 Hot path is O(n) allocation per delta + a full sync**
- `:203` copies the whole 5s window array on every delta; every delta also bumps → full sync + render. A fast
  model can exceed 200 deltas/s.
- Fix: `push` + trim from the head; events only set a dirty flag; a single ≤10Hz tick does the flush (reuse the
  spinner timer while it runs).

**P1-9** `spinnerCells()` (`:263`) computes N colors per frame but `:378` only uses `cells[0]` (this goes away once
the render switches to StyledText — each cell will have its own color).

### P2 — display/structure

**P2-10 Replace the 7 text nodes with a single `<text>` + `StyledText` (✅ verified working on both 0.4.2 / 0.8.1)**
- ✅ `ref.content = new StyledText([{ __isChunk: true, text, fg }, ...])` — each chunk keeps its own color (checked
  with `captureSpans`).
- Benefits: restores the per-cell gradient (given up in v1.0.2 / `769098e`); 4 refs → 1; mounting no longer syncs
  4 times.
- ✅ An empty `<text content="">` still takes **1 column** (gotcha #3's "~0 width" is actually 1 column). Going to a
  single node: idle content = `TPS -- | AVG -- | TTFT --` (no extra trailing space).
- 📖 `StyledText` and `RGBA` are both exported by `@opentui/core` (0.4.2 and 0.8.1); opencode redirects imports of
  `@opentui/core` to the host instance (binary `runtime-plugin`, `nodeModulesRuntimeSpecifiers: true`), so
  `new StyledText` is the same class the host renderer uses.
- Still purely imperative updates, consistent with gotcha #2.

**P2-11 Duplicated V1/V2 adapter code**: the prune timer is duplicated → move it into the core; collapse
`MeterDisplay`'s 7 props into `core`.

**P2-12 (optional, low priority)**
- Number width jumps (`9.99`→`10.0`→`100`) → `padStart` to a fixed width (TPS/AVG 4 columns).
- Remote server clock skew: samples use server timestamps, `now` uses the local clock → if skew > 1.5s it's
  permanently `--`. Fix: record a local receive time `localAt = Date.now()` for staleness/window calculations,
  and use the server timestamp only for TTFT (TTFT's start and end both come from the server, so they're
  consistent). **This can be done in T1** (cheap).

### Appendix: the likely root cause of gotcha #2 (📖, needs verification, only affects how AGENTS.md is worded)
- The opencode binary's `bun-plugin-solid` filter is `^(?!.*[/\\]node_modules[/\\]).*\.[cm]?[jt]sx…`: **tsx under
  node_modules does not go through the Solid compiler** and falls back to Bun's default react-jsx transform
  (`jsxDEV("box", {...})`, props evaluated once at creation) → `<Show when={sig()}>` is read only once. solid-js
  itself is actually redirected to the host instance.
- The conclusion "imperative updates only" stays the same; you can fix AGENTS.md's explanation in T6 (mark it
  "likely root cause").
- Corollary: under npm loading, the component function body still runs inside the host's Solid owner, so
  `onCleanup` probably works — but P0-3's guard is still required (defense in depth, and the local-file path
  differs).

## 3. Design decisions

### 3.1 Pure measurement region (T1)

The pure measurement functions must exist **byte-for-byte identically** in both `measure.ts` and `tui.tsx`
(`tui.tsx` must be single-file and self-contained, because users install via curl of the single file, and the
package `files` only ships `tui.tsx`).

- Use marker comments to delimit:
  ```
  // ==== BEGIN PURE MEASURE (keep in sync with measure.ts — test/sync.test.ts enforces) ====
  ...
  // ==== END PURE MEASURE ====
  ```
- In `measure.ts` the region is identical except for `export` keywords. The sync test: read both files, extract the
  region, strip `^export ` from the start of each line, normalize, and compare for equality.
- **The region must not contain** `RGBA`, `Buffer`, or any import. Token estimation must not use `Buffer` (it also
  removes the tsc error):
  ```ts
  const utf8Encoder = new TextEncoder()
  function estimateTokens(delta: string): number {
    return Math.max(1, Math.ceil(utf8Encoder.encode(delta).length / 4))
  }
  ```
  (Or count UTF-8 bytes by hand from charCodeAt to avoid allocation; either is fine — keep the existing test
  `"日本語" → 3`.)

Region contents (signatures; implementation is up to you, as long as the semantics hold):

```ts
const WINDOW_MS = 5_000, STALE_MS = 1_500, MIN_DURATION_MS = 1_000, MAX_CALIBRATION_RATIOS = 10
const MAX_TRACKED_MESSAGES = 32   // cap on the per-message map, to prevent leaks from messages that never complete

type DeltaKind = "text" | "reasoning" | "tool"
type DeltaSample = { at: number; rawTokens: number }   // at = local receive time (Date.now())
type MessageTrack = {
  createdAt?: number      // server time: V1 info.time.created / V2 step.started data.started
  firstAt?: number        // local time of the first output delta (for the generation window)
  lastAt?: number
  estimated: number       // raw estimated tokens summed over all kinds
  sawReasoning: boolean
  sawTool: boolean
}
type SessionStats = { totalOutputTokens: number; totalDurationMs: number; calibrationRatios: number[] }
type TrackerState = {
  useV2Events: boolean
  samplesBySession: Record<string, DeltaSample[]>
  rawSumBySession: Record<string, number>          // optional: running sum, avoids reduce
  messages: Record<string, MessageTrack>           // insertion order = LRU, evict oldest past the cap
  liveTtftBySession: Record<string, number>
  activeMessageBySession: Record<string, string | undefined>
  statsBySession: Record<string, SessionStats>
  thinkingBySession: Record<string, boolean>
  lastDeltaAtBySession: Record<string, number>     // used by the stale-thinking fallback
}

createTracker(): TrackerState
estimateTokens / formatTps / formatTtft / median / calibrationFactor   // keep existing semantics
speedTier(tps, tiers = DEFAULT_TPS_TIERS)   // configurable; default 20/50/100 (keeps existing tests valid)
ttftTier(ms, tiers = DEFAULT_TTFT_TIERS)
calculateLiveTps(samples, now, calibration)  // keep existing semantics and tests
liveTps(tracker, sessionID, now): number | undefined   // includes calibration
avgTps(tracker, sessionID): number | undefined

recordMessageStart(tracker, messageID, createdAt)
recordDelta(tracker, { sessionID, messageID, kind, delta, at /*local*/, serverAt? /*for TTFT*/ })
  // - samples.push + trim head older than at-WINDOW_MS (no array copy)
  // - first output delta: firstAt=at; if createdAt exists, TTFT = max(0, (serverAt ?? at) - createdAt)
  //   ⚠️ TTFT units: createdAt is server time, so use serverAt when available; the V1 legacy path has no serverAt,
  //      fall back to Date.now() (same as current behavior)
  // - kind==="reasoning" → thinking=true; "text" → thinking=false; "tool" → thinking=false
  // - sawReasoning / sawTool flags; activeMessageBySession[sessionID]=messageID
recordMessageCompleted(tracker, { id, sessionID, tokens:{output, reasoning}, finish? }): void
  // see the AVG/calibration rules in 3.2
clearSessionLive(tracker, sessionID)        // clear samples + thinking (doesn't touch stats/ttft)
discardMessage(tracker, messageID)          // step.failed
prune(tracker, now): boolean                // trim stale samples; stale-thinking fallback; returns "is anything still live"
resolveOptions(raw): ResolvedOptions        // pure: no RGBA; colors stay as hex strings (adapter converts)
  // - intervalMs: clamp [40, 1000], default 100
  // - cells: clamp [2, 16] integer, default 6
  // - colors: keep only /^#?([0-9a-f]{3}|[0-9a-f]{6}|[0-9a-f]{8})$/i; fall back to the theme preset if none left
  // - theme: tech|red|none; unknown → tech; none → spinner disabled
  // - tiers: only accept finite positive numbers; else defaults. If not ascending (slow<normal<fast, fast<ok), fall back to defaults
  // - slot: non-empty string, else "prompt.footer.status"
```

### 3.2 AVG / calibration rules (core of P0-1/P0-2)

When a message completes:
```
generationMs = firstAt/lastAt both present ? max(lastAt - firstAt, MIN_DURATION_MS) : 0
actual = tokens.output + (sawReasoning ? tokens.reasoning : 0)        // P0-2
excludeForTools = !sawTool && (finish === "tool-calls" || legacy path saw a running tool part)
                  // = "this step clearly made a tool call, but we never received tool input deltas" (legacy path / older versions)
if (excludeForTools) → don't add to AVG, don't add to calibration (better to drop one data point than to inflate)
else if (actual > 0 && generationMs > 0):
  stats.totalOutputTokens += actual; stats.totalDurationMs += generationMs
  if (estimated > 0) calibrationRatios.push(clamp(actual / estimated, 0.3, 3.0)), keep the last 10
Clean up messages[id]; only when activeMessageBySession[sessionID] === id (or unset): clear samples + thinking
```
- `finish` sources: V1 `AssistantMessage.finish?: string` (📖 SDK types); V2 `session.step.ended` `data.finish`.
- On the V1 legacy path (`message.part.delta`), mark a message's `sawToolPart` when a tool part goes running (use a
  `toolPartSeen` flag in MessageTrack, or pass it via a `recordToolBoundary(messageID)` function); then
  `excludeForTools = !sawTool && (finish==="tool-calls" || sawToolPart)`.
- **Tool events no longer clear live samples** (remove the clearSessionLive from tool events):
  - The 1.5s `STALE_MS` makes TPS show `--` naturally during tool execution;
  - Samples older than 5s are naturally pruned at the next step;
  - When the next step starts (V1: a new assistant message `message.updated` without completed; V2:
    `session.step.started`) do one `clearSessionLive` so the new step's window isn't polluted by the previous step.
- Live TPS includes tool input deltas (the model writing a big file has a reading too). The sample `kind` doesn't
  affect TPS computation.

### 3.3 Core scheduler (T2, in `tui.tsx`)

```
createMeterCore(options):
  tracker = createTracker()
  views = Set<() => void>                      // each MeterDisplay registers one flush function
  dirty = false; timer?: Interval
  markDirty() → dirty = true; ensureTimer()
  ensureTimer():
    want = anyLive(tracker)  (samples non-empty || some session thinking)
    period = anyThinking && spinner.enabled ? spinner.intervalMs : 250   // limits hot-path flushes to ≤10Hz while streaming
    if want and no timer (or period changed) → (re)create the interval
  tick():
    now = Date.now()
    if spinner is running → advance the particle frame; dirty = true
    stillLive = prune(tracker, now)   // trimming may also turn TPS from a number into "--" → must flush
    flush views (each view diffs and only writes/requestRenders on change; one requestRender per batch)
    if !stillLive and not thinking → clearInterval (idle-stop) — but first flush one final frame so "--" is shown
  safe views: each view wrapped in try/catch; on exception remove that view (P0-3)
```
- The event → flush latency is at most 250ms (100ms while the spinner runs); good enough for TPS display. TTFT is
  shown on the first token: to show it immediately, flush synchronously once on the "first token" event (optional).
- When the stream stops, the last sample becomes stale after 1.5s → the tick is still running (samples are within
  5s) → the TPS display goes to `--` → after 5s samples are cleared → stop.
- `dispose()`: clearInterval, clear views.

### 3.4 Single-node rendering (T2)

```tsx
function MeterDisplay(props: { core: MeterCore; palette: Palette; sessionID: () => string | undefined;
                               requestRender: () => void }) {
  let ref: TextRenderable | undefined
  let lastKey = ""
  const flush = () => {
    if (!ref) return
    if (ref.isDestroyed) { unsubscribe(); return }        // P0-3
    const segs = buildSegments(...)   // [{text, fg: RGBA}]
    const key = segs.map(s => s.text + "\u0000" + colorKey(s.fg)).join("\u0001")
    if (key === lastKey) return
    lastKey = key
    ref.content = new StyledText(segs.map(s => ({ __isChunk: true as const, text: s.text, fg: s.fg })))
    props.requestRender()
  }
  const unsubscribe = props.core.addView(flush)
  onCleanup(unsubscribe)
  return <text ref={(el: TextRenderable) => { ref = el; flush() }} fg={props.palette.muted} wrapMode="none">TPS -- | AVG -- | TTFT --</text>
}
```
- Segments: `TPS ` (muted) / TPS value (tier color or muted `--`) / ` | AVG ` / AVG value / ` | TTFT ` / TTFT value
  / when thinking: `" "` + N cells (each cell its own color: `lerpColor(bright, muted, i/(N-1))`, space cells
  muted).
- `colorKey(rgba)`: `rgba.toInts().join(",")` (📖 both versions have `toInts()`); or cache the color index directly.
- `wrapMode="none"` (📖 both versions' TextBufferOptions have it; default `"word"`): prevents line wraps when
  narrow. If tsc rejects it on the JSX props, drop it.
- The TS type of `StyledText` chunks: `TextChunk { __isChunk: true; text: string; fg?: RGBA; ... }` (both
  versions).
- V1 `sessionID` getter: `() => value.session_id` (V1 slot props are also reactive props; reading them inside the
  getter each time is fine).
- V2 `sessionID` getter: `() => input.sessionID ?? routeSessionID()` where `routeSessionID` reads
  `ctx.ui.router.current()` (type `Route = {type:"home"} | {type:"session", sessionID} | {type:"plugin",...}`).

### 3.5 Adapter event mapping (T3)

**V1 (`tui`)** — on top of the existing events:
| Event | Action |
|---|---|
| `session.next.text.delta` | `useV2Events=true`; recordDelta kind=text, serverAt=`timestamp`, at=`Date.now()` |
| `session.next.reasoning.delta` | same, kind=reasoning |
| **added** `session.next.tool.input.delta` | same, kind=tool, messageID=`assistantMessageID` |
| `message.part.delta` | when `!useV2Events` and field==="text", look up the part type: text/reasoning → recordDelta (no serverAt) |
| `message.updated` (assistant, not completed) | first time this id is seen: `recordMessageStart(id, info.time.created)` + `clearSessionLive(sessionID)` (new step) |
| `message.updated` (assistant, completed) | `recordMessageCompleted({id, sessionID, tokens, finish: info.finish})` |
| `session.next.tool.input.started` | **no longer clears**; only set thinking=false |
| `message.part.updated` (tool) | **no longer clears**; when status is running/completed/error, `recordToolBoundary(part.messageID)` (legacy-path tool marker) + thinking=false |
| **added** `session.idle` | `clearSessionLive(sessionID)` |
| **added** `session.error` | when sessionID present: `clearSessionLive` |

⚠️ The `message.updated` "first seen" check: `messages[id]` doesn't exist and isn't completed → treat as a new
step. The current code writes `messageCreatedAt` on every non-completed update; idempotency is needed (don't reset
firstAt).

**V2 (`setup`)**:
| Event | Action |
|---|---|
